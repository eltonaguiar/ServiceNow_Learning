# Lab Steps: REST Message Integration

**Time:** 30-40 minutes  

---

## Step 1: Create REST Message
**Breadcrumb:** System Web Services → Outbound → REST Message → New

| Field | Value | Notes |
|-------|-------|-------|
| Name | `GetExternalUser` | Descriptive name |
| Description | `Get user data from JSONPlaceholder API` | Optional but helpful |
| Accessible from | `This application scope only` or `All application scopes` | Use scope of your Update Set or follow lab preference |

Click **Submit**.

---

## Step 2: Create REST Method
Open the `GetExternalUser` REST Message → Related Links / HTTP Methods → New

| Field | Value | Notes |
|-------|-------|-------|
| Name | `getUser` | Method name |
| HTTP Method | `GET` | We're retrieving data |
| Endpoint | `https://jsonplaceholder.typicode.com/users/1` | Full URL |
| Content type | `application/json` (default) | Usually fine for JSON APIs |

Click **Submit**.

---

## Step 3: Test the REST Method
Open `GetExternalUser` → `getUser` method → Related Links → **Test** (or "Test REST Method")

- Click **Test**
- You should see a response with Status 200 and JSON body like:
```json
{
  "id": 1,
  "name": "Leanne Graham",
  "username": "Bret",
  "email": "Sincere@april.biz",
  ...
}
```

**If you get an error:** Check internet connectivity from instance, endpoint URL, or proxy/MID Server needs. For public APIs usually no MID Server needed.

**Success:** You can call the API from ServiceNow!

---

## Step 4: Parse Response & Do Something Practical
We want to update our test Incident with the external user's name/email.

**Option A: Business Rule (beginner-friendly)**

**Breadcrumb:** System Definition → Business Rules → New

| Field | Value |
|-------|-------|
| Name | `Update Incident with External User Data` |
| Table | `incident` |
| Advanced | Checked |
| When | `before update` or `async` (async safer for learning) |
| Insert/Update | Update checked |

**Filter Conditions (optional):** Add condition like `Short description` contains `Test REST Message Lab` to limit scope

**Script tab:**
```javascript
(function executeRule(current, previous /*null when async*/) {
  try {
    var rm = new sn_ws.RESTMessageV2('GetExternalUser', 'getUser');
    var response = rm.execute();
    var responseBody = response.getBody();
    var httpStatus = response.getStatusCode();
    
    gs.info('REST Response Status: ' + httpStatus);
    gs.info('REST Response Body: ' + responseBody);
    
    if (httpStatus == 200) {
      var data = JSON.parse(responseBody);
      // Do something practical - add work notes
      current.work_notes = 'External User: ' + data.name + ' (' + data.email + ')';
      gs.info('Updated incident with external user data');
    } else {
      gs.error('REST call failed with status: ' + httpStatus);
    }
  } catch (ex) {
    gs.error('Error in REST call: ' + ex.message);
  }
})(current, previous);
```

Click **Submit**.

## Step 5: Test End-to-End
1. Go to your test Incident (INC0010001)
2. Make a small update (e.g., add a work note or just save) to trigger the Business Rule
3. Refresh the form
4. Check **Work notes** - you should see "External User: Leanne Graham (Sincere@april.biz)"
5. Check **System Logs → System Log → All** for your gs.info messages

**If it doesn't appear:** Check Business Rule is active, conditions match, and logs for errors.
