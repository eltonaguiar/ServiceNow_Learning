## The one analogy that carries everything

**A ServiceNow instance is an office building full of filing cabinets.**

| Building thing | ServiceNow thing | What it means for you |
|---|---|---|
| The building | **instance** | Your company's own copy, at `https://yourcompany.service-now.com` |
| A filing cabinet | **table** | One kind of thing: incidents, changes, employees, servers |
| A folder in the cabinet | **record** | One incident, one change, one server |
| The printed form inside the folder | **form** | What you see when you open one record |
| A stack of folders you filtered out | **list** | Many records at once, e.g. "my open incidents" |
| The drawer attached to a folder | **related list** | Other records that belong to this one (tasks, approvals, SLA) |
| A keycard | **role** | What you are allowed to open |
| The lock on a specific drawer | **ACL** | The rule that checks your keycard on that drawer |
| Conveyor belts in the basement | **flow** | Automation that moves work without a human |
| A laminated checklist on the wall | **playbook** | A guided sequence a human follows step by step |
| The IKEA instruction booklet | **Guided Setup** | The vendor's own order of assembly, as a checklist |
| The project plan from head office | **Success Pack** (Now Create) | Phases, prerequisites and "done" criteria for a real deployment |
| A new appliance delivered to the building | **plugin** | Adds a capability; must be installed, licence permitting |
| Your own flat you may repaint | **application scope** | A boundary that stops your changes bleeding into the vendor's |
| A shipping container of your changes | **update set** | How changes travel from dev to test to prod |
| A practice building | **PDI** (Personal Developer Instance) | A free instance you can wreck freely |

Everything below is a consequence of that analogy.

## What you see when you log in

1. **The filter navigator** (top-left, or the **All** menu on newer UI). Type any module
   name — `incident`, `guided setup`, `tables` — and press Enter. This is the fastest way
   to navigate, and it teaches you the real names of things.
2. **The breadcrumb** at the top. It tells you where you are and it is clickable.
3. **A list** in the middle: rows of records, with a filter you can build by clicking.
4. **A form** when you open one row: fields on top, **related lists** underneath.
5. **Gear / ⋯ / right-click** on a form header → *Configure* → this is how you change which
   fields appear. You do not need to be a developer to do this.
6. **Your avatar** (top-right) → *Impersonate user*. This is the most useful learning tool
   on the platform: become the person who actually does the work and see their screens.

## Your first 30 minutes (zero risk, nothing to break)

- [ ] Log in. Note the URL — that is your instance name.
- [ ] Type `incident` in the filter navigator. Open **Create New**. Read every field label
      but **do not save**.
- [ ] Open any existing incident (demo data is fine). Scroll to the bottom. Those are
      related lists: Task SLA, Approvers, Additional comments.
- [ ] Right-click the form header → **Configure** → **Form Layout**. See how fields are
      chosen. Cancel out.
- [ ] Type `tables` → open **Tables & Columns**. Search `incident`. This is the map: every
      field on that form is a row in `sys_dictionary`.
- [ ] Open **System Definition > Application Menus**, search `incident`. This is why the menu
      items exist — each is a record pointing at a list or a form.
- [ ] Impersonate a non-admin user. Try to open the incident again. Notice what changes.
      **Stop impersonating** when done.
- [ ] Run `scripts/sn_probe.js` (see `docs/07-probe.md`) and look at the sheet it produces.

If you did that, you already understand more about ServiceNow than most people who have
watched three hours of videos: you have seen that the UI is just records about records.

## The five words people use loosely, defined properly

| Word | What people mean | What it actually is |
|---|---|---|
| **Module** | "the incident screen" | A menu entry pointing at a filtered list or a form |
| **Application** | "the app" | A bundle of tables, modules, roles and automation, usually from a plugin |
| **Guided Setup** | "the wizard" | A checklist of setup tasks with completion state — an ordered syllabus, not magic |
| **Flow** | "the automation" | A Flow Designer definition: trigger → actions → outputs |
| **Success Pack** | "the docs" | Now Create's implementation package: phases, prerequisites, acceptance criteria |

---

## Roles, in plain language

| Role | Roughly means |
|---|---|
| `admin` | Can change anything, including the schema. **Do not learn in this role** — it hides permission problems |
| `itil` | Can work IT tickets: view/update incidents, problems, changes |
| `snc_internal` | A normal employee (internal user) |
| `snc_external` | A customer/partner user who sees only their own things |
| module-specific (e.g. `sn_hr_core.case_writer`) | Granular rights inside one application |

The rule that saves you an embarrassing demo: **test as the role, not as admin.** Admin
bypasses ACLs, so everything "works" and nothing is proven.

## "I want to do X" → where to click

| Goal | Go here |
|---|---|
| Find any module | Filter navigator — type the name |
| Understand a table | `All > System Definition > Tables & Columns` |
| See why a menu item exists | `All > System Definition > Application Menus` (`sys_app_module`) |
| Change which fields show | Open a record → right-click header → Configure → Form Layout |
| See what an app needs installed | `All > System Applications > All Available Applications` |
| Build automation | `All > Process Automation > Flow Designer` |
| Learn a module's official setup order | Search "Guided Setup" in the filter navigator |
| Get the official implementation plan | Now Create via <https://learning.servicenow.com/lxp> |
| Practise without fear | Your PDI from <https://developer.servicenow.com/dev.do> |

## Glossary (A→Z, plain English)

**ACL** — Access Control List. A rule that decides who may read/write a record or field.
**Application scope** — A wall around your customisations so upgrades do not overwrite them.
**Breakdown** — The "by what" of a metric: incidents *by priority*, *by group*.
**Business rule** — Server-side code that runs when a record is inserted/updated/queried.
**Catalog item** — Something a user can request from a portal (laptop, access, HR letter).
**Choice list** — A dropdown whose options are configuration, not code.
**CI (Configuration Item)** — A thing you manage: a server, an app, a service.
**CMDB** — The database of CIs and how they relate. The platform's spine.
**Data policy** — Rules applied to data regardless of UI (imports, API, forms).
**Dictionary** — The definition of a field: type, length, mandatory, default.
**Flow** — Visual automation (Flow Designer). **Subflow** — a reusable flow inside a flow.
**Guided Setup** — An app's built-in ordered checklist of setup tasks.
**Impersonate** — Temporarily act as another user to see their experience.
**Indicator** — A metric definition (what to count, from which table, with what filter).
**Instance** — One ServiceNow environment (`dev`, `test`, `prod` are separate instances).
**Integration user** — A dedicated account used by an integration, with minimal rights.
**KPI / KPI Signal** — A metric with a target, and an alert when it trends wrong.
**MID Server** — A agent inside your network that lets the cloud reach on-prem systems.
**Now Create** — ServiceNow's implementation methodology site; Success Packs live there.
**PDI** — Personal Developer Instance: free instance for learning, from the developer portal.
**Playbook** — A guided, staged process a person follows (different from a flow).
**Plugin** — An installable capability bundle (e.g. software asset management).
**Record** — One row in a table.
**Reference field** — A field that points at a record in another table (e.g. caller).
**Related list** — Records in another table linked to this one.
**Remote Table** — An external REST API shown as a read-only ServiceNow table.
**Role** — A named permission bundle you assign to users or groups.
**Scripted REST API** — An API *you* publish from ServiceNow for others to call.
**REST Message** — A stored outbound HTTP request ServiceNow can send.
**SLA** — Service Level Agreement; in-platform it is a `task_sla` record with start/pause/stop rules.
**Spoke** — A prebuilt IntegrationHub connector to a specific product.
**Success Pack** — Now Create's implementation package for an app (phases, prereqs, criteria).
**sys_id** — The unique 32-character id of every record.
**Table** — A collection of records of one type (`incident`, `cmdb_ci`).
**Update set** — A container that carries configuration changes between instances.
**UI policy** — Makes fields mandatory/read-only/visible on a form, without changing the schema.
