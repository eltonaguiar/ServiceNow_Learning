### Fields — critical vs useful vs optional

**Critical** (get these wrong and the module misbehaves; mandatory-ness varies by instance):

- `table label + name (u_*)` — Naming is permanent-ish; renaming later breaks references.
- `application scope` — Global vs scoped decides whether you can use OOB tables freely.
- `roles on the app` — Without an app role, everyone is admin or nobody can see it.
- `state field via choice list` — Flows and reports key off state; design the states first.

**Useful:** form layout, list layout, ACLs generated by the builder, app menu

**Optional / nice to have:** custom UI pages, `workspace`

**Related lists worth configuring:** Auto-generated activities (task table), `Attachments`

> Mandatory is not a guess. Confirm it: `All > System Definition > Tables & Columns`, pick the table, filter the columns on `Mandatory = true`. The probe script does this for every table below in one run.

## Must know (the 5 facts that unlock the rest)

- Scoped app = cannot touch global tables/scripts without explicit cross-scope access. Decide scope before adding tables.
- Start from a table, not a form: data model first, then UI, then automation.
- Every app should ship with a role; otherwise security is an afterthought.

## Common mistakes

- Global scope by default, then wondering why upgrades conflict
- No app role
- Building UI before the data model
