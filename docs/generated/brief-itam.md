### Fields — critical vs useful vs optional

**Critical** (get these wrong and the module misbehaves; mandatory-ness varies by instance):

- `asset_tag` — Human key; must be unique and sticker-aligned.
- `model_id` — Links asset → model → manufacturer; drives contracts and licences.
- `state / substate` — Lifecycle truth: on order / in stock / in use / retired.
- `assigned_to` — Custody. Missing owner = lost asset.
- `install_status on the linked CI` — Asset and CI must agree or reporting lies.
- `contract start/end dates` — Renewal alerts and true-up run off these.

**Useful:** cost, cost_center, department, location, po_number, vendor, `warranty_expiration`, `gl_account`

**Optional / nice to have:** depreciation fields, `reserved_for`, `beneficiary`

**Related lists worth configuring:** CI (linked configuration item), `Contracts`, Asset history, `Licenses`, Transfer orders

## Must know (the 5 facts that unlock the rest)

- Assets (alm_asset) and CIs (cmdb_ci) are different records that point at each other. One asset can map to one CI; not everything is an asset.
- SAM Pro needs the software install data feed (SCCM/Intune/agent) or the license position is fiction.
- Licence compliance = rights (entitlement) vs installs/usage; you need both sides.

## Common mistakes

- Loading the asset register as CIs, or vice versa.
- Assuming SAM works without publisher-specific reconciliation rules.
- Ignoring contract renewal dates until the auto-renewal already happened.
