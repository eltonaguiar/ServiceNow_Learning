## Why this module first

Every module assumes people, places and groups already exist. Skip this and your incident has no caller, no assignment group, no SLA schedule and no reporting dimensions — the module looks broken when the data is simply absent.

### Fields — critical vs useful vs optional

**Critical** (get these wrong and the module misbehaves; mandatory-ness varies by instance):

- `sys_user.user_name` — Login id; also the join key for every HR/AD feed. Get the convention right once.
- `sys_user.active` — Deactivate, never delete — history and approvals reference it.
- `sys_user.department` — Drives reporting, approvals and cost allocation.
- `sys_user.manager` — Every approval flow and escalation path ultimately walks this.
- `sys_user_group.name` — Assignment groups are how work is routed; a group with no manager is an orphan queue.
- `cmn_location.time_zone` — Schedules and SLAs silently compute against the wrong clock without it.
- `cmn_schedule business hours` — An SLA on a 24x7 schedule against a business-hours team reports breaches that are arithmetic, not performance.

**Useful:** `company`, `location`, `cost_center`, `email`, `phone`, `title`, group type, parent location, parent department

**Optional / nice to have:** `photo`, `preferred_language`, notification preferences

**Related lists worth configuring:** User > Roles, User > Groups, User > Assigned to me, Group > Members, Group > Roles, Location > Child locations

## Must know (the 5 facts that unlock the rest)

- Load order is dependency order: company → location → department → cost centre → users → groups → schedules → categories. Reversing it creates orphans you will chase for weeks.
- Users are referenced by every record they ever touched. Import an update, never delete-and-recreate.
- Assignment groups are routing. If a group has no manager and no members, the queue is invisible.
- Business hours/schedules are foundation data, not SLA configuration — but SLAs break without them.
- A 20-row real load with correct references beats a 2,000-row import with wrong ones.

## Common mistakes

- Loading users before departments/companies (every user ends up with an empty org).
- Infinite recursion via a manager chain or a parent location pointing at its own child.
- Duplicate users from two feeds (HR + AD) with different user_name conventions.
- Deleting users instead of deactivating, breaking historical approvals.
- Groups created per person instead of per function.
- Skipping time zones on locations, so SLAs compute against UTC.
- No business-hours schedule, then blaming the SLA engine.
- Loading in production first because 'it's only reference data'.
