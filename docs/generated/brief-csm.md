### Fields — critical vs useful vs optional

**Critical** (get these wrong and the module misbehaves; mandatory-ness varies by instance):

- `account` — Everything (entitlement, SLA, reporting) hangs off the account.
- `contact / consumer` — Who reported it; drives auth and comms.
- `entitlement` — Decides whether service is included — get it wrong and you bill/deny wrongly.
- `case type` — Selects workflow and required fields.
- `priority + SLA` — Contractual, not internal, promise.

**Useful:** `product`, `channel`, `short_description`, assignment_group (internal tier)

**Optional / nice to have:** billing fields, special handling notes

**Related lists worth configuring:** `Cases`, `Entitlements`, `Contracts`, Work orders, `Contacts`

## Must know (the 5 facts that unlock the rest)

- Entitlement checks are the CSM-specific twist; without them SLAs are guesses.
- External users are real users with ACLs — test as the customer, not as admin.
- Case types are the CSM equivalent of catalog items: they define what an agent can even do.

## Common mistakes

- Skipping entitlement setup
- Testing the portal as admin
- One case type for every request
